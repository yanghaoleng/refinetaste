# RURU 加载优化（2026-10-26）

基线为 main `542ea5a`。仅在 RURU 构建末尾应用 `performance.py`，其他课堂继续原构建。保留自动进入下一章和输入框增高功能，不带入工作区其他任务的共享头像、页脚和图标草稿。

## 原因与处理

- 原 HTML 声明大量同步脚本和表情图预加载；首页 JS 又主动下载 296,804 字节的完整题库。主角色 PNG 为 1,379,088 字节，是主要图片负担。原字体只有 4,912 字节，不是主要慢因。
- 小界面图标直接内联，使用 `ruru-i-` 命名空间，避免 `bookmark` 等图标 ID 抢占按钮选择器。页脚的四个 16px 图标随 HTML 内联，音乐图标来自该课程现有公开 favicon；不再依赖跨域图片，不扩大 CSP。
- 页面只阻塞于小型主题脚本和一份关键样式，核心脚本合并后 defer。React 文字动效及案例工具延后至 load 后闲时或进入旧练习时加载，加载后保留原动效。初始计数、文本和静态头像可直接显示。
- 主角色变为 640px WebP，57,048 字节；保留原图。四张表情图合计从 333,394 降至 155,196 字节；不预加载全部表情，使用静态肖像作底图。随机肖像在 load 后解码成功才切换，避免空白。
- 首页/目录使用轻量元数据，完整题目按稳定章 ID 分片。旧练习先等对应章和必要案例工具，再进入题目；笔记只补其对应章。闲时仅预取上次章节或首章，不遍历整库，省流/2G 不预取。新连续会谈和互动卡沿原机制，不为进入它们强制下载旧练习题。
- 分片请求去重、超时、失败可重试、校验完整 ID 集合；旧页面的分片已过期时回退兼容 `course.json`。保留 0–95 题 ID、历史归档题、原本地存储键、原 API、Cookie 范围及两个路径。
- 静态文本预压 gzip，内容指纹资源 immutable，未版本化入口 no-cache，支持 ETag/304。保留旧表情资源 URL。压缩副本与最终原文逐一验证一致，不改变动态 API 缓存和鉴权。

修复 `542ea5a` 中健康卡无聊天表单时仍赋值 `onsubmit` 的空节点异常，保留原 `bindChatComposer` 增高绑定。

## 测量边界

相同 Air、公开 HTTPS、HTTP/1.1、Accept-Encoding:gzip、最多六个并发 GET。旧正式站 HTML 发现的脚本、样式/预加载和非 lazy 图片共 44 个 URL，合计 2,497,568 字节。候选结构为 5 个 URL，约 184KB；主图减少约 96%。HTML 另计，内联图标增加 HTML 少量体积。字体、CSS 背景、JS 动态请求和 API 不包含在这个 HTML 清单中；旧清单还含被 CSP 阻止的跨域图标，所以这是资源发现清单而不是浏览器实际瀑布。

工具当前不开放 Performance API；不能把合成 GET 耗时当作 FCP/LCP、可交互时间或用户网络实测。发布后以相同脚本重复公开 GET，并另验压缩/304/两个入口与实际页面。
